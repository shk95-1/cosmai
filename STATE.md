## 3. Boundaries
- **Standing approval (2026-08-23, the ledger is the closed #16; rule changes go to #74 `[rules]`)**: applying DDL to production (additive only — DROP, type changes and data loss excluded) · LLM (`CLAUDE_API_KEY`, hard stop $10, sending review and comment text is OK) · push, issues, gh · rebuilding and recreating the new stack's containers (`cosmai-*`) (the session does it directly, `up -d --force-recreate`). Production DB migrate/seed/UPDATE, running `analyze`, and writing the secret file are done **by the coordinator session itself, one command at a time** (a subagent dispatch is blocked by the classifier). Production DB actions (migrations, views, seeds) run only from the upstream checkout by the coordinator session (D7, #192).
- **Approval every time**: rebuilding, stopping or restarting an old-stack container (postgrest · data-portal · dashboard · tubedepth-api; `cosmai-postgres` is the new stack but its restart and the first start on a data directory are approval items too) · anything of the `DROP` kind · a budget increase. Per-case approval is recorded in the comments of the relevant `ops`/`decision` issue, which are the ledger.
- **Evaluation before main (2026-09-05, #229 R3)**: the user's evaluation is required only for a change that touches production (DDL · seeds · views · `stack/` · `db/migrate.sh`), a rule site (AGENTS.md · `.claude/agents/` · `tool/checks/` · `.githooks/`), or one a reviewer escalates — grade A and waves alike; everything else the coordinator merges after its one review round (grade B) or on its green gate with a sampled review afterwards (grade C outside `contracts/`).
- **Deploy condition (2026-09-05, #228 D5′)**: `tool/stack-build` and a `db/migrate.sh` apply take only a tree whose class-A run is green, enforced by `tool/checks/deploy-gate` (#233) — the CI check run on the commit, or the local tested-tree record when `gh` cannot answer. `COSMAI_FORCE_DEPLOY=1` overrides the refusal with a reason written to the ops issue's journal. Main may carry a red unrelated to any merged change for at most a day and is fixed forward; production never does.
- **Autonomous run (goal #255, from 2026-09-14 until it closes)**: while goal #255 is open, (1) the approval-every-time list above is replaced by *dump first, then act, then journal* — every destructive or state-changing production step takes a dump named in the ops issue's journal before it runs (§2); (2) the user's evaluation before main (#229) is replaced by the drift review on goal #255 after the run — agent review by grade is unchanged; (3) no LLM spend beyond the existing ledger — #113 is implemented but not switched on; (4) every tier-1 or tier-2 judgement leaves an `Autonomous decision` comment on its issue in the form goal #255 fixes; (5) the judgement rule is goal #255's — verified certainty first, reversibility where nothing checkable settles it, consistency with the baseline on shared surfaces. What still stops the run: secret values, a force push to main or a wave branch, `--no-verify`, anything published outside the two repositories. D7 stands unchanged. When goal #255 closes this bullet is removed and the text above is in force again.
- **Forbidden**: modifying an archived old repository (editing the local stack and data-portal configuration is the exception, with no push) · extending the old cosmai platform · printing secret values or committing `.env` · `--no-verify` and force push · forging a TLS fingerprint or a client identity in order to defeat a block, and evading authentication or access control. An ordinary client library, and a publicly available extraction tool used against a public endpoint, are neither — #35 is the precedent rather than the exception: the Cloudflare challenge on the oliveyoung review API was answered by a current OpenSSL in the image (§2), not by a forged fingerprint. A collector may still bind itself to a self-identifying UA as its own contract, and commerce does (`collectors/commerce/contract.py`, the value's reason is #35); that is that collector's choice now, not this rule's requirement (fork #91, user decision 2026-09-07).

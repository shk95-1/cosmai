# stack — operational know-how (bought by measuring it)

The contract is `contracts/entrypoints.md` §Schedule·§DB connection knobs, the intent and the approval boundaries are `STATE.md`, and what is running now is `tool/status`. Only the **traps** those three do not mention are written here. A defect is an issue — it is not written here.

- **Starting with `docker start` runs the old image.** If the image changed, use `docker compose up -d --force-recreate <service>`. Recreating the new stack (`cosmai-*`) is done directly by the coordinator (`STATE.md` §3).
- **`tool/stack-build`'s second stage dies inside compose interpolation without `stack/.env`** — that is a missing variable, not a build failure. `.env` only carries paths, no secret values (`stack/env.example`).
- **The analyze concurrency lock (`analysis/locks.py`) cannot see a process that started before the lock existed.** Every cron run after cutover sits inside the lock, so this only matters when running the old checkout by hand on the host.
- **There is one GPU. The gemma4 cron window is 08:00–16:00 UTC daily (17:00–01:00 KST), suspended while the `0 8` line is absent (#242).** The line in `stack/crontab.d/analyze` opens that window when restored. Overlapping `cosmai retrieval embed` (380k chunks, 20.6 minutes of idle GPU) with it costs both sides 5h38m (measured on the fork, #28). An advisory lock cannot see the other repo's process, so `embed` avoids the window when it is active. The 8h width is an upper-bound estimate, not a measured T: the full pass took 6h44m (#32), while the first-night `--missing` pass took 2h34m (run 25, #131). The normal-night T is unmeasured; whoever measures it next records it. The two repos decide together whether to narrow the window after that measurement.
- **The host's ollama address is the Tailscale interface.** `OLLAMA_URL`'s default `http://100.102.193.98:11434` is the Windows-side address WSL2's mirroring inherits, and **it disappears when Tailscale is off**. The bridge gateway, the LAN, and `host.docker.internal` were all unreachable from inside a container (measured 2026-08-25). The place to swap it out is `stack/.env`, and an unreachable night is not a quiet zero but a failed run.
- **Leftover suite containers**: `tool/checks/test` starts a `cosmai-test-postgres-<port>` (tmpfs, holds RAM) per worktree and removes it with a trap. If the shell dies to SIGKILL, it is left behind — `tool/status`'s `test-leftovers` section shows it, and the next run on the same port prints the owning container's name (and, since #226, its `cosmai.worktree` label) and stops. If it belongs to another worktree, do not remove it -- tell its owner. Remove only a container your own run started, and only after `docker ps --filter publish=<port>` shows it and `pgrep -af <port>` shows no client still connected to it.
- **The image does not carry the retrieval extra** (`stack/Dockerfile`'s `uv sync --no-dev`). Inside a container, `cosmai retrieval …` only passes `--help`. Upstream will carry it the day the search cron (#55) exists.
- **The image base changes the TLS fingerprint**: an OpenSSL 3.0 base is blocked by oliveyoung's review API, and a 3.5 base (current) gets through. `tests/stack/test_image_tls_stack.py` holds the floor. Full story in #35.
- **`tool/checks/test` syncs `--extra retrieval`, `stack/Dockerfile` does not (until #55).** Cost is `kiwipiepy-model` (88 MB sdist, no wheel) plus `kiwipiepy` (11.5 MB), paid once per uv cache; every run after that is near zero.
- **Rewinding the youtube flatten cursor: delete the `flatten.artifact` records first** (#280, N5 of #275's review). `tubedepth.flatten_progress` is one row and rewinding it is the obvious way to re-flatten a range — but a pass reads its retry list (the `flatten.artifact` records with attempts left) *and* the artifacts after the cursor, and after a rewind an artifact can be in both. Nothing corrupts, every write is an upsert; what breaks is the counting, because the run row then charges that artifact twice and the failure rate on the screen is not the one the data has. So: `DELETE FROM tubedepth.jobs WHERE kind = 'flatten.artifact' AND target IN (<the artifacts in the rewound range>)`, then move the cursor.
- **A permanent `payload_unreadable` record clears only when a job asks for that target again** (#280, N7 of the same review). `flatten` cannot produce a payload it does not have, so the record is final on the first attempt and the artifact is never retried. It goes away when `work` fetches that target again under a **new** artifact row ahead of the cursor — which happens only if something queues that target. Production's 3,707 old-fleet artifacts (rows whose payload volume never came with them) are the case where nothing ever will: they will sit as `failed` records for good, and that is the record doing its job, not a backlog to clear by hand. Re-flattening them needs the volume, not a rewind.
